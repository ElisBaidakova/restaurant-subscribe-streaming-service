# Restaurant Subscribe Streaming Service

## О проекте

Потоковый ETL-сервис для обработки событий о рекламных акциях ресторанов.

Сервис получает события из Apache Kafka, определяет активные рекламные кампании и объединяет их с данными о пользователях, подписанных на рестораны. Результаты обработки сохраняются в PostgreSQL и передаются в выходной Kafka topic для дальнейшего использования downstream-сервисами, например для отправки push-уведомлений.

Потоковая обработка реализована с использованием Apache Spark Structured Streaming.

## Логика обработки

Сервис получает события о рекламных кампаниях из Kafka, фильтрует активные акции и объединяет их с данными о подписках пользователей из PostgreSQL. Сформированные события передаются в PostgreSQL для хранения и в Kafka для дальнейшей обработки.

## Что реализовано

* Организовано чтение событий из Kafka в режиме потоковой обработки.
* Реализован разбор JSON-сообщений по заданной схеме.
* Добавлена фильтрация рекламных кампаний по времени начала и окончания акции.
* Реализовано объединение потоковых событий с данными о подписках пользователей из PostgreSQL.
* Добавлено формирование времени срабатывания рекламного события.
* Реализована обработка микропакетов с использованием `foreachBatch`.
* Результаты каждого микропакета записываются в PostgreSQL и передаются в выходной Kafka topic.
* Настроено checkpointing для Spark Structured Streaming.
* Параметры подключения к Kafka, PostgreSQL и Spark вынесены в отдельный конфигурационный файл.
* Учетные данные не хранятся непосредственно в основном коде приложения.

## Ключевые технические решения

### Apache Spark Structured Streaming

Для получения данных из Kafka используется `readStream`, а обработка результатов выполняется через `writeStream`.

Поток работает в режиме `append`, а `foreachBatch` используется для выполнения операций записи для каждого микропакета.

### Apache Kafka

Kafka используется как источник входящих событий и как выходной канал для дальнейшей обработки.

Подключение настроено с использованием:

* `SASL_SSL`;
* `SCRAM-SHA-512`;
* SSL-сертификата;
* отдельных input и output topics.

### PostgreSQL

PostgreSQL используется для получения информации о подписках пользователей и сохранения результатов обработки.

Подключение к PostgreSQL выполняется через JDBC.

### Checkpointing

Для Spark Structured Streaming настроено сохранение checkpoint:

```python id="l92x6n"
.option("checkpointLocation", config.CHECKPOINT_LOCATION)
```

Checkpoint используется для сохранения состояния потоковой обработки и восстановления после перезапуска приложения.

## Системные требования

* Python 3.9+
* Apache Spark 3.3+
* Java 8 или 11
* Apache Kafka
* PostgreSQL 12+
* SSL-сертификат для подключения к Kafka

Для работы приложения необходим доступ к Kafka и PostgreSQL.

## Развёртывание и запуск

1. Клонировать репозиторий.
2. Настроить параметры Kafka и PostgreSQL в `config.py`.
3. Передать учетные данные через переменные окружения или локальный файл с секретами.
4. Запустить Spark-приложение:

```bash id="wz7wf5"
spark-submit streaming.py
```

> Файлы с паролями, сертификатами и другими секретами не должны добавляться в Git-репозиторий.

## Конфигурация

Основные параметры приложения вынесены в `config.py`:

* параметры подключения к Kafka;
* названия input/output topics;
* параметры PostgreSQL;
* Spark application name;
* зависимости Spark;
* путь к checkpoint.

Учетные данные для подключения к внешним сервисам не должны храниться в репозитории. Для локального запуска используются переменные окружения или отдельный файл с секретами, исключённый из Git.
